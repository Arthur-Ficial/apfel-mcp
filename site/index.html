MCP tools for apfel

Give apfel the web and your files.

apfel runs Apple's model 100% on-device, so on its own it can't reach the internet or read your files. apfel-mcp adds four small tools that do exactly that - and nothing else. Each returns a result already trimmed to fit apfel's tiny 4096-token window.

How to use it

Install, attach, ask.

You need apfel working first (brew install Arthur-Ficial/tap/apfel, macOS 26 + Apple Intelligence).

1

Install the tools

One tap, four commands land on your PATH.

brew install Arthur-Ficial/tap/apfel-mcp
2

Attach one to apfel with --mcp

apfel launches the tool as a subprocess and discovers what it offers. Start with the compound one:

apfel --mcp $(which apfel-mcp-search-and-fetch) # then ask
3

Ask a question that needs it

The on-device model decides when to call the tool, reads the trimmed result, and answers.

apfel --mcp $(which apfel-mcp-search-and-fetch) \
      "What did Apple announce this week?"

For a long --chat session with these tools, add --context-strategy sliding-window --context-max-turns 4 so the (large) tool results don't overflow the 4096-token window.

The four tools, in detail

Small, honest, one job each.

Every result is hard-capped so it fits apfel's context. Where a tool has real limits, they're stated plainly - no surprises.

Before you start

What you need.

1.apfel, working. apfel-mcp plugs into apfel - install it first: brew install Arthur-Ficial/tap/apfel.
2.macOS 26 (Tahoe), Apple Silicon, Apple Intelligence on. That's apfel's requirement; apfel-mcp itself is plain Python.
3.Nothing else. No API keys, no accounts, no cloud. The web tools hit the open web directly; everything else stays on your Mac.
Why so small? apfel's context window is 4096 tokens - a few paragraphs. These tools are built to hand the model a tiny, useful result that fits, instead of a huge page it can't read. That's the whole design.
